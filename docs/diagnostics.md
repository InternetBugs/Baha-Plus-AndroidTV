# 日志与反馈

普通用户的入口为 **设置 → 日志与反馈**，简体与繁体均可用。操作只需方向键、确认与返回键，不要求开发者模式、ADB、系统日志权限或配套手机 App。

## 使用流程

1. 选择“开始记录”，然后返回应用复现问题。开始新记录会替换上次记录。
2. 回到此页选择“停止记录”。也可直接选择“发送日志与反馈”，导出时会自动停止记录。
3. 可以先“预览日志”并复制最近的内容。导出的报告包含仍保留的完整轮转日志。
4. 选择“发送日志与反馈”，用同一局域网的手机扫描电视二维码，下载 `.txt` 文件。
5. 手机页面提供本仓库 GitHub Issues 新反馈入口。填写现象、复现步骤、预期结果、发生时间，并附上日志文件或粘贴内容。提交需要 GitHub 账号；用户也可以把日志通过已有联系方式发送给开发者。
6. 电视上也可使用“系统分享文件”，通过设备上已安装且支持接收文本附件的应用发送。不保证每台电视都安装了分享应用。
7. “清除日志”会停止记录并删除应用内部的日志及缓存导出文件；用户已下载、复制或发送的副本不受影响。

## 保存与隐私

- 默认关闭，不随安装、启动或重开应用自动采集，不自动上传。
- 事件字段采用允许列表，只接受既定事件名、有限状态、布尔值、数值与有限错误码。
- 记录页面类型、登录／访客状态、验证与广告阶段切换、网页主框架网络错误码／HTTP 状态、原生播放器状态、快进位置、画质、前后台及内存警告。
- 环境包含应用真实版本、Android/API、设备制造商与型号、ABI、WebView 版本、当前进程 PSS 与资源设置。
- 不记录账号 ID／昵称、密码、Cookie、授权二维码或令牌、请求响应原文、搜索内容、片名、浏览／媒体地址、设备序列号、系统 logcat。
- 捕获 Java 未处理异常时，只写异常类型和本应用栈帧，不写异常消息；继续交给系统原有异常处理。系统强杀、ANR 与原生崩溃不能保证留下新增的异常记录，但此前落盘的事件仍保留。
- 事件写入单个有界后台队列，两个文件各最多 256 KiB，超限轮转。队列满时丢弃诊断事件，不等待播放器。导出报告另有设备信息头，略大于事件文件总量。
- 进程重建后停止采集，保留已有文件；最多保留三份近期缓存报告，方便系统分享读取。数据不参与 Android 备份。

## 手机下载

下载服务只在用户打开传送窗口后启动，绑定当前网络的一张内网 IPv4 网卡，仅提供当前报告。地址包含 192 位随机令牌；必须匹配完整路径与 Host，请求不能枚举目录、读取任意文件或修改应用数据。页面转义报告内容，无脚本、外部资源、跨域授权或访问日志，并设置禁止缓存和 Referrer 策略。

传送使用局域网 HTTP，手机应处于可信的同一网络。报告内容不通过第三方二维码图片服务，二维码在电视本地生成。窗口关闭、应用停止显示或 10 分钟到期会关闭监听及活动连接。每个连接还有单独超时，避免阻塞过期和退出。

访客 Wi-Fi、AP 隔离、防火墙、仅 IPv6 或系统的局域网访问限制可能阻止手机连接；遇到此类网络可改用系统分享。没有自动部署的公网日志服务器，也不在应用内保存 GitHub 开发者凭据。下载页面明确说明下载完成不等于已提交反馈。

新增 JVM 测试位于 `app/src/test/java/app/bahaplus/tv/diagnostics/`，覆盖关闭时不采集、停止边界、字段允许列表、轮转上限、重启保留、清除、崩溃脱敏、报告下载、HTML 转义、随机路径／Host／方法限制、关闭与过期。Android Lint 与调试 APK 构建均纳入验证。
