# 系统 WebView 的语法兼容层

2026-11-13 后续原生 HTTP 迁移已将该兼容层限制在按需创建的登录 WebView 内；首页、搜索、账号资料及播放不再经过它。以下保留兼容器实现与早期官网播放验证记录。当前路径见 [原生 HTTP 迁移](native-http-migration.md)。

启用条件是实际内核的语法能力，不按 WebView 版本名单决定。启动时在尚未载入官网的 WebView 中，用 `new Function()` 只解析、不执行包含私有方法、私有访问器与逻辑赋值的探测代码。语法受支持时，官网使用原来的加载路径，不创建编译 WebView，也不拦截或转换脚本。探测失败才启用客户端转换；实际提供程序版本仅用来设置编译目标，不使用应用伪装后的 User-Agent。

启用后，兼容层处理 `https://ani.gamer.com.tw/` 与 `https://i2.bahamut.com.tw/` 下的外部 `.js`／`.mjs` 资源，不维护单个脚本文件名单。这个来源边界用于区分官方静态代码与其他数据；账号 HTML、PHP/API、媒体、其他站点及第三方广告脚本使用原加载路径。当前页面内联代码也保留原加载方式，转换层不重写 HTML。新增官方静态脚本文件无需加入兼容名单。

转换时重新获取原始公开 HTTPS 脚本，不附带 Cookie 或 Authorization，不跟随重定向；成功且 MIME 为 JavaScript 的响应才交给 Babel。Babel standalone 7.28.5 在仅加载本地 APK 资源的独立 WebView 中运行，该页面禁止联网、外部导航、文件访问及框架加载。JavaScriptInterface 只存在于此本地编译页面，官网页面继续使用原有的来源与文档范围消息机制。

编译器把下载的源码作为文本处理，不在本地编译页面执行官网代码，不注入广告、年龄或授权流程的替代实现。输出保留原始 URL、模块导入与官网逻辑；传统脚本会将包含 API 补丁的完整输出交给设备自身的 `new Function()` 进行解析检查。转换后的代码由原官网页面按原来的顺序执行。

83 的实际回归另发现官网辅助脚本调用了缺失的 `String.replaceAll`。转换响应会加入经过 Chrome 74 语法编译的 core-js 3.47.0 对应补丁，只有该方法不存在时才安装，重复加载不替换已有实现。补丁通过 Babel AST 插在程序指令之后、官方语句之前，保留原来的 `"use strict"` 和非严格脚本行为；不会用字符串前缀使严格模式失效。没有注入完整的浏览器 API 补丁集，正常内核也不会加载此补丁。当前编译器修订为 `babel-7.28.5-corejs-3.47.0-v4`，会自然失效旧修订的缓存。

转换结果以源码内容、实际内核目标和编译器修订的 SHA-256 为键，存放在应用私有缓存中，最多 64 个文件、24 MiB。每次仍读取当前官网脚本，源码变化会使用新键；缓存节省再次编译的成本，不是离线播放器。单份输入上限 2 MiB、输出上限 4 MiB。编译 WebView 在最后一次任务后空闲 10 秒释放，页面销毁时也释放。首次编译有额外 CPU 与内存开销。

下载、超时、编译或输出检查失败时返回原始加载流程，不返回空脚本冒充成功。官方主播放器仍发生解析错误时保留原生兼容性提示。语法转换不补齐浏览器 DOM API、媒体解码、DRM 或官方站点自身的运行错误；不能据此保证所有旧内核都能播放。

运行证据和对应 APK 哈希见 [模拟器验证](emulator-validation.md) 与 [构建验证](build-validation.md)。反馈设备仍需安装测试，x86 模拟器结果不能替代 32 位 ARM 电视验收。
