# 已确认的首版规格

确认日期：2026-11-12。来源：酥鱼在本地 Codex 的 grilling 访谈及最终“全部同意”。

## 目标与设备

面向低性能安卓电视与电视盒子，优先保证遥控操作和观看体验。主验收设备为酥鱼截图中的 TCL 55Q9K。实机截图显示四核 Cortex-A73、最高约 1.39 GHz、32 位运行模式与 `armeabi-v7a, armeabi`；商品页标注 4 GB 内存、64 GB 存储与 G52 MC1。商品参数不能代替实机检测。

最低系统先采用 Android 7.0／API 24；电视连接 ADB 后核实，低于该基线时重新评估。兼容性必须覆盖 32 位运行环境。

## 必做功能

首页、搜索、番剧详情与选集、单账号登录、播放、继续观看、官方支持范围内的追番和观看进度同步。

下载、投屏、评论和弹幕后置；不考虑多账号。安装 APK 后直接使用，无需自建服务器或强制配套手机 App。

2026-11-14 后续范围更新：酥鱼要求移植 Baha-Plus 的弹幕接口到当前原生播放器，并明确电视端只观看、不提供发送功能。弹幕开关和设置界面放在进度条下方；设置在控制条内展开，可通过遥控器调整字号、不透明度、显示范围及滚动／顶部／底部类型。此项更新上述弹幕后置的安排。

## 技术与官方机制

Kotlin、原生 View／RecyclerView 和 Media3。参考现有 Baha-Plus 的业务及 JavaScript 适配器，电视界面独立实现。

官方 WebView 负责登录、验证、广告及授权，正片使用原生播放器，保留必要的官方会话和实际进度回传。续播与观看进度完全沿用官方机制，不增加独立本地记录。

2026-11-13 酥鱼要求添加手机扫码登录，并复用官方接口；同日酥鱼在交互模拟器中测试后反馈“账号功能完全正常”。2026-11-14 酥鱼进一步要求删除账号密码登录，仅保留二维码扫码登录，更新此前的官方网页登录回退与遥控光标方案。

电视扫码页提供刷新二维码和返回，方向键移动焦点、确认键执行。账号输入、验证码与两步验证在手机官方网页完成；电视通过官方扫码接口接收会话，再由原生 HTTP 验证账号身份。协议及实际验证范围见 [扫码登录记录](qr-login.md)；目标电视上的扫码、账号交接与遥控操作仍需实机验收。

## 布局与交互

左侧导航、右侧海报网格；继续观看置顶；静态封面、不自动播放预告、不使用液态玻璃。焦点清晰，返回列表恢复先前位置。

全部核心操作仅依赖方向键、确认键和返回键：

- 控制条隐藏：确认切换播放／暂停，左右每次快退／进 10 秒，上下呼出控制条。
- 控制条显示：方向键选中，确认执行。
- 返回先关闭控制条或选集面板，再返回详情。
- 控制条提供画质、倍速与选集。

自动续集默认开启，可关闭；最后一集结束后提供重播、选集和返回详情。

低资源模式默认开启，减少界面动画、封面尺寸、图片缓存和预加载，保留焦点提示。视频默认自动画质，也可选择获准清单中的档位并保存偏好；界面节省与画质独立。

默认简体中文，可切繁体，片名及简介保留官方原文，搜索兼容简繁输入。

## 验收

必须在目标电视完成登录、搜索、追番与选集，连续播放至少一整集，反复快进和返回，退出重进检查续播，并到官方端核对观看记录和追番状态。记录启动、遥控响应与内存，检查焦点丢失、持续掉帧、音画不同步和播放失败。

源码检查、离线适配器测试、Android 构建和真机验证是不同的证据；每项按实际执行结果报告。
