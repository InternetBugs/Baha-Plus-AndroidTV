# 非登录功能的原生 HTTP 迁移

实现与验证日期：2026-11-13，Asia/Taipei。

普通 `debug`／`release` 入口的首页、搜索、详情、账号资料、追番、历史和播放均使用 Kotlin HTTP 请求。扫码登录、网页登录与登出保留原官方浏览器会话机制。播放实验与后续迁移将按用户要求合入 `main`，没有发布新的正式版本，也没有新增下载依赖。版本基线保留 `main` 的 `0.3.1`／versionCode 4。

## 请求路径

| 功能 | 原生实现 |
| --- | --- |
| 首页 | 官方 App `mobile_app/anime/v4/index.php`，合并新番、热门和新上架分组 |
| 搜索 | `anime/v1/search.php`，合并原输入与繁体转换结果，按作品 ID 去重 |
| 详情与集数 | `OfficialAnimeApi` 的公开 App API 路径，按作品与影片 ID 校验 |
| 身份与追番列表 | 原生 HTTP 请求 `mygather.php`，在本地解析静态标记并读取分页；请求前后核对账号 |
| 观看历史 | 原生 HTTP 请求 `anime/v3/history.php`，保留官方断点，跳过已下架作品 |
| 加入／取消追番 | 精确匹配作品的官方追番参数，取得官方 CSRF Token 后请求 `want2play.php`／`delgather.php` |
| 播放 | 复用原 `experiment/native-playback-api` 的 `NativeApiClient`、Cookie 容器、策略与观看时钟 |

收藏列表与播放会话初始化仍使用官方静态 HTML；原生代码将它作为资料读取，不执行其中的 JavaScript。广告公共配置也只读取其中的 JSON 数组。官方没有返回 JSON 的页面没有被描述成 JSON API。

`InertHtml` 只实现上述官方标记所用的标签、类名、属性和后代选择，丢弃脚本、样式和注释，限制输入大小、节点数和深度。页面结构变化或身份不明确时返回失败，不通过 WebView 回退读取。分页特别处理仅有 `?page=2` 的链接，以保留浏览器的路径解析语义。

## 会话与登录

`OfficialPortal` 只负责登录与登出：

- `MainActivity.onCreate()` 不再创建 WebView。只有用户打开登录时才创建，并先载入本地空白文档，再探测语法能力、启动扫码流程。
- 本地空白文档显式允许初始化导航；初始化超过 15 秒仍未完成会释放登录页面并提示重开，避免渲染进程不可用时一直占住登录入口。
- 原来的 `qr-login.js` 保留二维码申请、授权轮询、过期刷新及前后台暂停；保留“使用账号密码登录”和遥控光标。
- `login-session.js` 只通知网页登录完成，不通过桥接传递身份、收藏或历史。
- 扫码／网页登录完成后，原生 HTTP 用官方 Cookie 核对身份并读取账号资料。未核对为真实账号时不接受为登录成功。
- 关闭登录界面时销毁官方 WebView、释放编译器，并清除 Activity 对 WebView 的引用。旧内核编译器只可能在登录页面运行。
- 原生账号请求和每次播放使用 CookieManager 的内存快照及独立 Cookie 容器；响应 Cookie 不写入日志或新的磁盘存储。原生会话中的 Cookie 轮换不会和旧快照形成重复请求项。
- 开始登录、登出和 Activity 销毁会使旧账号操作失效。取消和替换请求同时阻止已经排入主线程队列的过期结果。
- 没有官方 Cookie 时直接显示访客。明确指向官方登录入口的重定向可以作为会话失效信号，HTTP 层不会跟随它；其他重定向拒绝处理。
- 登出继续清除 CookieManager 与官方 WebStorage，取消旧原生操作并清空账号界面。

保留的适配器仅为：

```text
qr-login.js
login-session.js
tv-navigation.js
```

旧的首页、搜索、收藏／历史、年龄提示、广告、HLS 解析、播放器接管、时钟和停止播放适配器及其调用方均已删除。对应的旧 JavaScript 测试由原生协议、数据校验和生命周期测试替代，扫码与旧内核兼容测试继续执行。

## 原生播放

播放协议代码由 `src/nativeApi` 移至 `src/main` 共享，原 `nativeApi` 实验入口仍默认使用独立访客 Cookie；普通入口向同一实现传入当前官方登录 Cookie 快照。没有复制另一套播放协议。

普通入口的 Media3 控制条继续支持画质、倍速、快进／后退、选集、自动连播和生命周期暂停。画质使用 Media3 发现的当前视频轨道，通过轨道约束切换，不再依赖网页 HLS 解析。

原生流程依次完成设备初始化、影片与策略读取、官方分级对应的原生确认、真实视频广告、广告事件、授权取源和设备／开始播放通知。广告累计至少 30 秒实际媒体推进，且开始事件成功后才允许跳过；结束事件成功后才请求正片。暂停、缓冲、跳转和后台不计入观看时长。

正片按实际媒体推进累计观看时间，每累计 60 秒请求官方进度接口。暂停、退后台、跳转、退出及自然结束也会提交对应的状态／进度；已结束页面的结果不再影响新页面。进度采用实际媒体时长，保留官方接近片尾的完成标记语义。

服务端拒绝、家长密码要求、广告不足所需时长、格式改变或取源失败会停止并提供原生重试／返回，不回退到网页播放器。短广告的完整回退链、家长验证交互和目标 ARM 电视仍未完成验收。

## 本地验证

- 普通与 `nativeApi` 构建分别执行 JVM 测试、Lint 和 APK 构建。
- JavaScript 源码与 WebView 74 编译资源继续执行扫码、网页登录通知与兼容器测试。
- 原生测试覆盖首页分组合并、双查询去重、图片来源限制、分页与身份变化、追番 CSRF 参数、无脚本 HTML 解析、HTTP 来源／重定向／大小限制、Cookie 轮换、请求取消、广告门槛与播放协议。
- 独立访客模拟器 `BahaPlusTV_WebView83_API29`，Android 10／API 29、32 位 x86，专用 ADB 5093、设备 `emulator-5594`。原生浏览／播放测试未调用 WebView，不作为 83 内核验证。扫码测试另用同一 AVD 配置的干净独立数据文件，实际提供程序为 **74.0.3729.185**；未使用真实用户账号。
- 普通安装包已观察到真实首页、原生搜索、详情与选集，原生分级确认、实际视频广告及正片播放。官方进度响应多次为 `ok`，包含累计 60 秒后的定时上报。
- 播放中已检查暂停、前进 10 秒、360p 选择、1.25 倍速、退后台暂停和返回详情。上述浏览／播放阶段的应用 WebView 数量均为 0。
- 干净的 74 环境实测扫码申请成功、授权倒计时显示、刷新后获得新倒计时，以及切换官方账号密码登录页；返回后官方登录 DevTools 页面数量为 0。对象统计中的 WebView 数量仍可能在垃圾回收前短暂保留，不能当作仍有活动页面。未保存二维码、授权链接或账号数据。

当前迁移后的账号收藏、追番变更、登录账号续播以及扫码后的完整账号交接尚未使用真实账号验收。此前用户对旧版账号功能的验收反馈不代替这些新增原生请求的验收。
